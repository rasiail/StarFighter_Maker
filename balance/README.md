# 밸런스 데이터 작업 방법

코드·생성 데이터 대조 기준: 2026-09-22.

`balance/*.xlsx` 네 파일이 밸런스 데이터의 원본입니다. `balance/generated/*.csv`와 `src/data/generated/*`는 변환 결과이므로 직접 수정하지 않습니다.

| 변경하려는 항목 | 원본 파일 |
| --- | --- |
| 레벨별 필요 경험치 | `levels.xlsx` |
| 기관포·미사일 피해, 장전, 사거리, 탄속 | `weapons.xlsx` |
| 스테이지, 웨이브 목표, 적 체력·보상, 생성 규칙 | `waves_enemies.xlsx` |
| 카드 목록, 효과, 등장 조건 | `cards.xlsx` |

각 파일의 `Guide` 시트에서 열의 의미를 확인할 수 있습니다. 노란색 데이터 셀만 수정하고 영문 ID는 참조 관계를 이해한 경우에만 변경합니다. 수식과 분석 시트는 게임 데이터로 내보내지지 않습니다.

## 변환

```sh
python tools/balance/build.py
# 또는
npm run balance:build
```

변환기는 외부 Python 패키지를 사용하지 않습니다. XLSX의 데이터 시트를 읽어 다음 결과를 만듭니다.

```text
balance/generated/              사람이 Git diff로 검토하는 CSV
src/data/generated/balance.json 엔진 중립 데이터
src/data/generated/balance.js   현재 웹 게임용 ES Module
```

변환 과정에서 ID 중복, 누락된 참조, 음수·0 수치, 레벨 연속성, 스폰 확률과 거리 범위를 검사합니다. 검증에 실패하면 생성 파일을 갱신하지 않습니다.

`npm start`, `npm run check`, `Play_Game.bat`도 실행 전에 변환기를 호출합니다. 문서를 저장한 뒤 평소처럼 게임을 시작하면 최신 값이 반영됩니다.

`balance.json`은 특정 엔진의 클래스나 필드명을 요구하지 않습니다. Unity는 JSON DTO 또는 ScriptableObject importer, Godot은 JSON/Resource importer를 추가해 같은 데이터를 사용할 수 있습니다. 엔진별 이름과 저장 형식 변환은 원본 XLSX가 아니라 `balance.json`을 입력으로 구현합니다.

## 수치 시뮬레이션

멀티 미사일 카드 해금 및 빔 에너지 감사는 `node tools/balance/weapon-audit.mjs --runs=300`으로 실행합니다. 결과는 `balance/reports/weapon-audit/report.md`와 `report.json`에 저장됩니다. 실제 탄창/빔 에너지 함수를 사용하며 멀티 보유 여부를 반영합니다. 캠페인 비교는 기관포+미사일만, 빔은 별도 단발/홀드 및 16개 에너지 강화 조합 벤치입니다. 기존 `simulate.mjs`/`review.mjs`는 멀티 보유 여부와 빔을 반영하지 않으므로 현재 무기 해금 구조의 비교에는 이 감사 결과를 사용하세요. 실제 조준·피격·특수 적 행동은 생략한 수치 모델입니다.

현재 필요 경험치는 XLSX 테이블 값이며 첫 5개는 60 / 150 / 300 / 500 / 750입니다. 전 구간을 이전 곡선의 7.5배라고 설명할 수 없습니다. 스테이지 경험치 배율은 0.85 / 0.9 / 1.4이고 웨이브 목표는 총 337개입니다. 무기·스테이지 현재 수치는 [README](../README.md#전투와-성장)를 참고하세요.

`reports/latest/`를 포함한 기존 보고서는 생성 당시 데이터와 가정의 실험 기록입니다. 폴더 이름이 현재 데이터와의 일치를 보장하지 않습니다. 과거 19.31분·종료 레벨 15 등의 수치를 현재 런의 측정 결과로 사용하지 않습니다. `xpRequirementScale`은 원본 요구량에 추가로 적용하는 시험 배율이며 기본값은 1입니다.

주 사용 흐름은 **AI에게 목표 제시 → 후보 조합 자동 실행 → JSON 분석 → Markdown 리뷰**입니다. 웹 화면은 보조 확인용입니다. 예를 들어 "멀티 미사일을 약화하면서 평균 20분에 맞춰줘"라고 요청하면 아래 도구로 후보를 탐색합니다.

```sh
npm run balance:review -- --target-minutes=20 --runs=100
# npm 없이 실행할 때는 원본 변환 후 실행
python tools/balance/build.py
node tools/balance/review.mjs --target-minutes=20 --runs=100
```

`balance/reports/latest/review.json`은 AI가 읽을 전체 후보·가정·데이터 해시·성장 타임라인이고, `review.md`는 사람이 읽을 리포트입니다. 기본 56개 조합에서 멀티 장전 배율과 웨이브 적 수 배율을 탐색합니다. 후보는 기본 100회씩 빠르게 탐색하고 선택안과 전략 비교는 `--runs` 횟수로 검증합니다. `--search-runs=200`, `--reload-scales=1,1.5,2`, `--enemy-scales=0.8,0.9,1`, `--multi-ratio-limit=1.2`, `--seed=104`, `--out=balance/reports/experiment`로 조건과 출력 위치를 지정할 수 있습니다.

추천은 균형 카드 전략 기준 목표 시간에 가장 가까운 탐색 후보입니다. 멀티/표준 비율 제한은 사용 비중을 같게 맞춘 초기 무강화 지속 DPS에 적용하는 임시 설계 조건입니다. 후보별 총 적 수와 성장량, 전략별 시간과 탐색 시간 민감도도 보고합니다. 도구는 원본 XLSX를 수정하지 않습니다. AI는 리포트를 검토한 뒤 사용자의 적용 요청에 따라 원본을 갱신합니다.

게임 서버를 실행한 뒤 실제 서버 주소의 `/balance.html`에서 **Balance Lab**을 엽니다. 반복 횟수, 기관포·미사일 명중률, 기관포 사격 비중, 멀티 미사일 사용 비중, 표적당 탐색·기동 시간을 바꿔 다음 결과를 비교할 수 있습니다.

- 예상 런 시간과 10~90% 범위
- 시간에 따른 레벨·전투 DPS·누적 표적 수
- 공격·생존·균형·무작위 카드 선택 전략
- 무기별 일제 피해와 지속 DPS 기여도
- 적 구성과 레벨별 요구·누적 경험치

명령줄에서는 같은 계산 엔진을 사용합니다.

```sh
npm run balance:simulate
# 반복 횟수와 시드 지정
node tools/balance/simulate.mjs --runs=1000 --seed=104
# 상세 JSON 출력
node tools/balance/simulate.mjs --runs=100 --json
```

기본 `events` 모델은 기관포와 미사일의 개별 발사·명중, 과잉 피해, 탄창 소모, 전체 재장전, 무기 전환, 미사일 탄착 시간과 전함 선체·함포 연쇄 격파를 시간 순서로 계산합니다. 기동력·속도는 표적 접근 시간, 안정성·유도 성능은 명중률에 작은 추정 보정을 줍니다. 이 계수들은 실측 전 가정이며, 플레이어 피격·사망과 적 공격 예산은 아직 포함하지 않습니다. 절대 플레이 시간을 확정하기보다 데이터 변경 전후의 상대 변화와 비정상적인 성장 구간을 찾는 용도입니다.

## 적 공격 압박 시험

`node tools/balance/incoming-review.mjs --applied=true --runs=60`은 저장된 조정 전 데이터(`reports/enemy-pressure/baseline.json`)와 현재 데이터를 비교합니다. 결과는 `reports/enemy-pressure/review.json`, `review.md`에 기록합니다. `--baseline=경로`, `--out=경로`로 비교 기준과 출력 위치를 지정할 수 있습니다. `--applied`를 생략하면 두 하향 후보를 비교합니다.

60초 동안 격추·회복·강화 없이 550kts로 비행하는 압박 시험입니다. 3개 스테이지에서 직진·완만한 회피·적극적 회피를 각각 반복하며, 단독 보스도 비교합니다. 게임의 비행·사격·적 미사일 유도 함수를 공유하고 실제 피해, 조준 조건, 공격 예산, 동시 미사일 수와 발사 간격을 적용합니다. 평지·고도 800m와 정해진 요 기동을 가정하므로 실제 완주율이나 숙련도별 사망률을 의미하지 않습니다.

일반 공중 적은 기총만, 엘리트·보스는 미사일도 발사합니다. 엘리트 미사일은 피해 14·최고 속도 700m/s·선회 0.65rad/s, 보스는 피해 20·850m/s·0.9rad/s입니다. 기관포·대공포 피해는 4입니다. `attack-policy.js`의 현재 미사일 상한은 4발, 공통 발사 간격은 엘리트 2.5초·보스 1.5초이며, 지상·해상 사격 후보는 가까운 2곳입니다.

## 실제 게임과 시뮬레이터의 차이

- 실제 게임: `Waves.elite_ratio` → 생성 데이터 `eliteRatios` → `config/stages.js` → `missions.fillWave()`로 연결합니다. 배열 인덱스는 `waves`와 일치해야 합니다. 이 전달 누락으로 출격·HUD 갱신이 중단됐던 오류는 수정했습니다.
- 전투/피격 시뮬레이터: `formation.js`의 `ELITE_AIR_PROBABILITY = 0.20`을 공중 생성에 적용합니다. 실제 게임의 웨이브별 0~25% 배분과 같지 않습니다.
- 실제 게임도 지상/해상 분기로 엘리트 요청량을 못 채웠을 때 요청량을 생성 수로 기록하는 제한이 있습니다. 비율은 보장된 실측 생성 비율이 아닙니다.
- 탄창 재장전은 게임과 이벤트 시뮬레이터 모두 `magazine.js`의 누적 부채 방식을 사용합니다. 기준 15초/30초가 항상 실제 대기시간인 것은 아닙니다.
- `smartAim` 반경이나 실제 조종 숙련도 등은 시간 시뮬레이션의 정확한 실측 모델이 아닙니다. DPS 기여율 4:3:3 또는 목표 20분이 검증 완료됐다는 결론을 내리지 않습니다.

## 보고서의 최신성 확인

리뷰 JSON의 `dataSha256`는 `JSON.stringify(BALANCE)`의 SHA-256입니다. 파일 원문 해시와 다릅니다. 데이터 해시뿐 아니라 시뮬레이션 코드·옵션·시드도 같아야 결과를 비교할 수 있습니다. 이번 문서 정리에서는 과거 보고서 수치를 재계산하지 않고 기록임을 표시했습니다. 현재 비교가 필요하면 새 출력 폴더에 위 도구를 실행하고 실행 조건을 함께 보관하세요.

단위 테스트는 2026-09-22 기준 60개 중 49개 통과·11개 실패입니다. 탄창·화력·공격 정책 등의 기대값과 구현을 다시 대조해야 합니다. 상세 검증 범위는 [개발 문서](../docs/ARCHITECTURE.md#검증)에 기록합니다.

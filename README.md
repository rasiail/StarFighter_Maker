# StarFighter — 3D 비행 슈팅 프로토타입

F-104를 조종하며 적을 처치하고 카드로 기체를 강화하는 Three.js 기반 웹 게임입니다. 현재 구현은 **스테이지별 3·4·5웨이브 → 보스 → 정비창 → 다음 스테이지**로 이어지는 런 구조입니다.

문서 확인 기준: 2026-09-22, 현재 작업 트리의 코드. 장기 기획과 구현 현황은 [기획안](문서/StarFighter키우기_기획안_v2.md), 개발 구조는 [ARCHITECTURE](docs/ARCHITECTURE.md)를 참고하세요.

레벨·무기·웨이브/적·카드는 `balance/`의 XLSX 원본에서 관리합니다. 수정 후 `npm run balance:build` 또는 `python tools/balance/build.py`를 실행하면 CSV 검토본, 엔진 중립 JSON, 웹용 JS가 생성됩니다. 자세한 절차는 [밸런스 데이터 안내](balance/README.md)를 참고하세요.

게임 서버의 같은 주소에서 경로를 `/balance.html`로 바꾸면 Balance Lab에서 평균 런 시간, 성장 곡선, 적 구성, 무기 DPS, 경험치 곡선과 카드 선택 전략을 시뮬레이션할 수 있습니다. CLI에서는 `npm run balance:simulate`를 사용합니다.

## 실행

`npm start`와 배치 실행은 Node.js와 Python이 필요합니다. 게임 런타임은 번들러나 npm 패키지 설치 없이 동작하지만, 브라우저 테스트 도구는 별도 패키지가 필요합니다.

```sh
npm start
# npm을 사용할 수 없다면
node tools/serve.js
```

기본 주소는 `http://127.0.0.1:8000/index.html`입니다. 배치 파일이 선택한 포트가 다르면 콘솔에 출력된 주소를 사용합니다. Node 서버는 `127.0.0.1`에 바인딩하며 `PORT` 환경변수로 포트를 변경할 수 있습니다.

Windows의 `Play_Game.bat`는 자신의 프로젝트 폴더에서 Python으로 밸런스를 변환한 뒤 Node 서버를 시작합니다. 서버 준비가 끝나면 실제 포트의 게임 주소를 브라우저로 엽니다. `PORT` 설정을 따르며, 포트가 이미 사용 중이면 빈 포트로 실행합니다. Python과 Node.js가 필요합니다. HTML 파일을 직접 여는 대신 HTTP 서버를 사용하세요. Three.js r128, fflate 0.8.2, FBXLoader와 웹 폰트를 외부에서 로드하므로 인터넷 연결도 필요합니다.

### PS 패드

브라우저에서 표준 매핑으로 인식되는 패드를 지원합니다. USB/블루투스로 연결한 뒤 게임 페이지에 포커스를 두고 버튼을 한 번 눌러 인식시킵니다. 연결 직후나 메뉴에서 복귀할 때 누르고 있던 버튼은 떼고 다시 눌러야 동작합니다.

| 입력 | 동작 |
| --- | --- |
| 왼쪽 스틱 | 피치·롤 (데드존 18%, 기울기에 비례한 조작) |
| 오른쪽 스틱 | 자유 시점 |
| L1 / R1 | 좌 / 우 요 |
| R2 / △ | 가속 / 감속 |
| ○ 탭 / 0.18초 이상 홀드 | 미사일 / 기관포. 탭 동작은 버튼을 뗄 때 실행 |
| L2 탭 / 0.28초 이상 홀드 | 타깃 변경 / 타깃 캠 |
| □ | 표준 → 멀티 → 표준 순차 전환 |
| × | 전투·정비창에서 스킬 카드창 열기 |
| Options | 옵션 열기·닫기 (강제 카드 선택 중에는 취소 불가) |
| 방향키, × 또는 ○ | 메뉴·카드 이동 및 선택. 정비창에서는 ×가 강화 전용이므로 출격은 ○로 선택 |

옵션의 음량 슬라이더는 방향키 위/아래로 포커스를 옮기고 좌/우로 조절합니다. 패드 연결 해제·창 포커스 이탈·메뉴 전환 시 패드 전투 입력을 초기화합니다. 표준 매핑이 없는 장치는 잘못된 버튼 작동을 피하기 위해 읽지 않습니다. 실제 PS4/PS5 패드의 브라우저별 연결·조작감 검증은 별도로 필요합니다.
## 전투와 성장

| 무기 | 기본 피해 | 탄창 | 발사 간격 | 기본 락온 거리 | 재장전 기준값 |
| --- | --- | --- | --- | --- | --- |
| 기관포 | 18 | 무제한 | 0.05초 | HUD 보조 1000m | 해당 없음 |
| 표준 미사일 | 55 | 20발 | 0.3초 | 2000m | 15초 |
| 멀티 미사일 | 85 | 8발 | 0.5초 | 3000m | 30초 |

- 미사일은 탄창을 소진하면 전체 재장전합니다. 실제 대기시간은 위 기준값에 고정되지 않습니다. 발사마다 재장전 부채가 쌓이고, 재장전 중이 아닐 때 초당 1초씩 줄어듭니다. 소진 시 `기준값 × 0.333 + 남은 부채`가 대기시간이 됩니다. 계산식은 [개발 문서](docs/ARCHITECTURE.md#미사일-재장전)를 참고하세요.
- 멀티는 서로 다른 락온 대상에 기본 최대 4발을 발사하며 `multiSalvo` 카드로 6·8발까지 늘어납니다. 실제 발사 수는 표적 수와 잔탄에도 제한됩니다. 락온이 없으면 1발을 무유도로 발사합니다. 출격 전체의 총 탄약 제한은 없습니다.
- 스마트 기총 어시스트는 기본 활성화입니다. 1000m 이내 표적에 대해 기수 전방 200m에 투영한 보어사이트와 리드 마커를 비교합니다. 기본 보조 반경은 140px이며 `smartAim` 단계당 20% 증가합니다. 어시스트를 끄면 110px 정렬 판정을 사용합니다. HUD 범위는 탄환 충돌 거리 제한과 다릅니다.
- 처치 경험치를 즉시 지급하며 레벨업마다 선택권 1회를 적립합니다. 초기 필요 경험치는 60 / 150 / 300 / 500 / 750 XP이며 원본은 `balance/levels.xlsx`입니다.
- 레벨업 순간에는 전투가 계속됩니다. X/알림 클릭 또는 웨이브 전환 후 미사용 선택권이 있으면 카드창을 열며, 전부 선택할 때까지 전투·재장전·예약 타이머가 정지합니다.
- 6종 스탯은 각각 0~5단계입니다. 표준 랙은 단계당 +4발, 멀티 랙은 +2발, 재장전은 기준값 -10%, 화력은 피해 배율 +0.1입니다. 카드 조건과 나머지 효과는 [개발 문서](docs/ARCHITECTURE.md#성장과-카드)를 참고하세요.
- 보스 격파 후 정비창에서 무료로 체력과 탄창을 보충합니다. 성장·점수·미사용 선택권을 유지한 채 다음 스테이지로 이동하며 마지막 정비창 출격 시 런 완료입니다.
- 새 출격과 NEW RUN은 성장을 초기화합니다. 재도전은 런을 시작한 스테이지로 돌아갑니다. 저장·영구 성장은 없습니다.
- 격추 시 기체를 표시한 채 관성 이동·회전·연쇄 폭발을 8초간 진행한 뒤 패배 화면으로 전환합니다.

## 스테이지

| 스테이지 | 웨이브별 목표 | 엘리트 비율(웨이브 순서) | 동시 존재 / 공중 공격 후보 | 일반 공중 적 HP / 보스 HP |
| --- | --- | --- | --- | --- |
| STAGE 01: CANYON SCOUT | 10 / 16 / 22 | 0% / 10% / 15% | 30 / 4 | 80 / 2200 |
| STAGE 02: OCEAN TRIDENT | 18 / 24 / 30 / 36 | 0% / 10% / 15% / 20% | 36 / 5 | 100 / 3400 |
| STAGE 03: METROPOLIS SHIELD | 25 / 30 / 36 / 42 / 48 | 0% / 10% / 15% / 20% / 25% | 42 / 6 | 120 / 4800 |

웨이브 목표 합계는 337개(사막 48, 해상 108, 도시 181)이며 보스는 별도로 3기입니다. 전함은 선체와 함포 2개가 각각 목표를 차지하므로 목표 수와 기체 수는 같지 않습니다. 스테이지 경험치 배율은 0.85 / 0.9 / 1.4입니다.

실제 게임은 웨이브 전체 목표에 엘리트 비율을 곱해 반올림한 수를 생성 예산으로 사용합니다. 공중 적의 고정 30%가 아닙니다. 일반 공중 적은 MigFish, 엘리트는 Su307(HP 250), 보스는 MechaFish FBX/PBR 모델을 사용하며 로딩 실패 시 절차적 모델을 사용합니다. 지상/해상 생성 분기 확률은 25%이며 해상 전함은 목표 슬롯 3개가 남아 있어야 생성합니다.

공중 AI는 INTERCEPT / ENGAGE / EXTEND / RECOVER 상태를 사용합니다. 근접 교차 후 3.5초간 이탈하고 전방 지형을 예측해 회피합니다. 일반 적은 기관포만, 엘리트·보스는 기관포와 미사일을 사용합니다. 기관포는 일반/엘리트 3발, 보스 4발 점사입니다. 미사일은 거리 700~2200m, 조준 유지 1.1초 등의 조건을 만족해야 합니다.

공중 사격 후보는 보스 → 2200m 이내 엘리트 → 거리 순으로 스테이지 예산만큼 선택합니다. 탱크·함포는 별도로 가까운 2곳을 선택합니다. 적 미사일 동시 상한은 4발, 공통 발사 간격은 엘리트 2.5초·보스 1.5초입니다. 기관포·대공포 피해는 4, 엘리트 미사일은 14, 보스 미사일은 20입니다.

## 검증

```sh
npm run check
# 생성된 데이터로 정적 검사만 실행
node tools/check.js
# scratch의 임시 스크립트를 제외한 단위 테스트
node --test "tests/*.test.js"
# 실행 중인 서버를 대상으로 Puppeteer 출격 회귀 검사
node tools/sortie-smoke.cjs
```

2026-09-22 재확인: 54개 모듈의 문법·연결·초기화 부작용 검사 통과. 단위 테스트는 **60개 중 49개 통과, 11개 실패**입니다. 전부 통과한 상태가 아닙니다. `npm test`는 현재 `node --test`이므로 `scratch/test.cjs`까지 자동 발견할 수 있습니다.

같은 날짜에 `sortie-smoke.cjs`로 세 스테이지의 출격·카메라·HUD·배기·전체 웨이브·보스·정비창 전환을 확인했습니다. 배치 파일을 통한 실제 실행에서도 레이더·중앙 HUD·적 표식을 확인했으며, 사용자가 정상 동작을 확인했습니다. 기존 `npm run test:smoke`는 별도 Playwright 스크립트이며 오래된 탄창·적 수 기대값이 남아 있습니다. 설치·환경변수와 검증 공백은 [개발 문서](docs/ARCHITECTURE.md#검증)를 참고하세요.

## 최근 수정과 남은 차이

- 스테이지 어댑터에서 `eliteRatios`를 누락해 출격 및 매 프레임 미션 갱신이 실패하던 오류를 수정했습니다. 이 오류가 카메라·HUD·배기 갱신을 막았습니다.
- 카메라 초기화와 추적 계산을 `src/camera/follow.js`로 통일했습니다. 순항 후방 거리는 9.375m, 속도 비율 80% 이상에서는 12.5m입니다.
- `Play_Game.bat`는 자신의 폴더에서 밸런스를 빌드하고, 서버 준비 후 실제 포트의 주소를 엽니다. Node 서버는 `Cache-Control: no-store`를 사용합니다. 기존 문제 탭의 캐시가 직접 원인이었는지는 확인하지 못했습니다.

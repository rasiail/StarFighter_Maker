# [게임 기획서] 프로젝트 스타파이터 (Project Starfighter)

> 코드 대조 갱신: 2026-09-22. 1~10절은 장기 비전과 초기 기획 기록, 11절은 웹 프로토타입 플레이 규칙이다. 현재 구현 상태와 차이는 12절에서 구분한다. 아래 Unity·Steam·6소켓 진화 구상은 현재 저장소에 구현된 기능을 뜻하지 않는다.

---

## 1. 개요

* **프로젝트명**: 프로젝트 스타파이터 (가제) / 스타파이터 키우기
* **장르**: 3D 아케이드 플라이트 슈팅 + 뱀서라이크(로그라이트 모듈 조립)
* **개발 엔진**: 현재 웹 프로토타입은 Three.js r128 / JavaScript ES Modules. Unity는 후속 이전 구상.
* **타깃 플랫폼**: 최종 종점은 Steam 패키지 (오토리도리와 동일). 초기 프로토타입은 AI 프로그래밍 시험 목적의 웹(Three.js) 단일 실행 환경에서 출발.
* **프로젝트 포지셔닝**: Jet Universe의 정식 한 축이 아니라, 여러 소재(메카물고기 등 기존 세계관 요소 포함)를 자유롭게 섞어보며 검증하는 실험적 사이드 프로젝트.
* **핵심 컨셉**: 2세대 요격기 F-104 스타파이터를 원형으로 삼아, 실존 전투기의 항공역학적 상호 배제 규칙을 바탕으로 '나만의 가상 실험기'로 분기·진화시켜 나가는 아케이드 공중전.
* **개발 배경**: 현재 수습탈락으로 무직 상태, 3개월의 여유 기간 동안 이직 활동과 병행해 포트폴리오 겸 개발 작업으로 버티컬 슬라이스 제작 목표. 오토리도리 대비 캐릭터 리깅·애니메이션 공수가 없고(좌우대칭 강체 어셈블리), AI 3D 생성 성공률이 높으며, AI 아트 활용에 대한 유저 거부감도 낮을 것으로 판단되어 3개월 스코프에 더 적합하다고 결론.

## 2. 시놉시스 및 배경 서사

> 하늘에서 메카물고기가 침략해왔다. 전투기들은 모조리 격침당했지만, 어쩐 일인지 — 물고기를 닮은 유선형 실루엣 덕인지 — F-104 한 기만이 살아남았다. 이 한 대의 기체를 강화하여 하늘을 탈환하라.

* 갤러그·인베이더식 고전 슈팅의 사전 배경 설명 수준으로 가볍게 다룬다. 게임플레이 메카닉에 깊게 얽매이지 않는 플레이버 텍스트 수준.
* 구시대의 유물로 전락한 2세대 요격기가 끝없는 적 편대의 탄막 속에서 살아남기 위해 실시간으로 기체를 개조한다는 원 시놉시스와 정합성을 유지.

## 3. 핵심 재미 포인트 및 차별화 요소

* **스탯 투자가 시각적 진화로 직결되는 카타르시스**: 특정 스탯을 한계(Max)까지 투자하면 파츠가 교체되는 극적인 기체 진화 연출.
* **항공역학적 인과가 맞물린 모듈러 규칙**: 델타익 장착 시 수평미익 비활성화 등, 실존 공력 원칙에 기반한 모듈러 규칙으로 언제나 균형 잡힌 실루엣 유지.
* **실존 기체의 재해석**: 완제품 카피 지양, F-104의 정체성(바늘코, 원통형 코어)을 유지한 채 가상의 파생 실험기를 완성하는 독자적 빌드 감성.
* **에이스컴뱃의 관습을 깨는 RPG 성장 요소**: 에이스컴뱃 시리즈는 기체별 무기 데미지가 표준화(고정)되어 있으나, 본작은 뱀서라이크식 스탯 성장으로 이를 깨뜨린다.
* **수렴진화는 인정하되 계보 간 메리트로 차별화**: 진화 트리가 결국 비슷한 실루엣으로 수렴하는 것은 자연스러운 현상으로 받아들이고, 대신 계보(F-15형 vs F-16형)마다 서로 다른 플레이 경험을 부여하는 데 집중.

## 4. 비주얼 방향

### 4.1 기체 데폼 비율
* 완전한 SD(2~3등신)가 아닌 건담 MGSD·SDCS급의 **5등신 비율**을 목표. "그 비율의 에이스컴뱃"이라는 니치 포지셔닝.
* F-104, F-14 데폼 테스트 완료 및 만족스러운 결과 확인 — 목표 비율에 부합.
* 데폼 원칙: 동체 길이 압축, 폭 확장, 캐노피·엔진·흡기구 강조, 주익-미익 간격 단축. 단, **날개 후퇴각·미익 형태·흡기구 위치 등 실루엣을 결정짓는 각도는 실물 그대로 유지** — 이를 통해 원형 기체의 정체성을 보존.

### 4.2 아트 스타일 (2단계 이원화)
* **정적 프로모/컨셉아트용**: 히데타카 텐진(반다이 MG 건담 박스아트 작가) 스타일 — 3D 모델링 기반 위에 회화적 명암·반사광을 얹는 듯한, PBR은 아니면서 매끈하고도 거친 질감. 프라모델 박스아트 특유의 정확한 데칼·마킹 재현, 부대 로고·콜사인 강조, 다이나믹한 순간 포착이 특징.
* **인게임 3D 렌더링용**: 텐진 스타일은 정적 2D 아트에 최적화된 방식이라 실시간 렌더링에 직접 적용은 무리. 대안으로 **PS1(플레이스테이션 1) 레트로 3D 스타일** (에이스컴뱃3 시절 그래픽) 검토 중 — 저폴리곤, 아핀 텍스처 매핑, 버텍스 워블/스내핑, 디더링, 256x256 저해상도 텍스처가 특징. 저폴리 데폼 실루엣과 미학적 궁합이 좋고, 이전 민초(조선 소울라이트) 기획에서 이미 PSX 미학을 다뤄본 경험 있음. Unity URP 셰이더 그래프로 구현 검토.

### 4.3 UI/연출
* 4:3 브라운관 비율, 에이스컴뱃 스타일의 그린 군용 HUD.

## 5. 핵심 모듈러 아키텍처 및 진화 시스템

### 5.1 6대 파츠 소켓 체계
| 소켓 | 기본 상태 | 진화 옵션 예시 |
|---|---|---|
| 주익 (Main Wing) | 직선익 | 삼각 델타익 / 후퇴 삼각익 |
| 어깨 (Forebody) | 미장착(원통) | 가동식 카나드 / LERX(스트레이크) |
| 미익 (Empennage) | T자형 미익 | 쌍열 수직미익(트윈 테일) |
| 흡기구 (Intake) | 측면 포드 인테이크 | 복부·턱밑 인테이크 |
| 엔진 코어 | 단발 제트 노즐 | 쌍발 엔진 확장 블록 |
| 외장 옵션 | 윙팁 연료탱크 | 윙팁 미사일 레일 / 배면 건포드·로켓 런처 |

### 5.2 진화 분기 구조
* 랜덤 카드가 아닌, 특정 스탯 5레벨(Max) 달성 시 상위 프레임 진화 카드가 해금되는 **"임계값에서의 능동적 선택"** 구조.
* 예: 선회력 Max 달성 → 요격형 델타 프레임(그리펜 계보) vs 중형 후퇴 프레임(Su-27 계보) 중 선택.
* **계보별 업그레이드 속도 차별화**: F-15류 중전투기 계보는 업그레이드 단계를 길게, F-16류 경량 계보는 빠르게 — 예: 쌍발 엔진 스킬 해금에는 체력(HP) 스탯 다량 투자가 선행조건.
* **빌드 계획 vs 발견의 균형**: 에이스컴뱃의 기체 해금 계보도처럼 '?'로 가려진 노드가 있는 스킬 조합 도표 제공. 정확한 조건 공개 수준(수치 vs 힌트)은 프로토타입 단계에서 실제 플레이 테스트를 통해 결정.

## 6. 스탯 시스템

### 6.1 스탯 축 (6종)
| 분류 | 스탯 | 역할 |
|---|---|---|
| 기동 | 즉각 기동력 (Mobility) | 순간 선회각/롤 기동 — 얼마나 빨리 방향을 꺾는가. 경량 계보(F-16형)의 특화 축. |
| 기동 | 제어 지속력 (Stability) | 선회 후 오버슈트 없이 정밀하게 멈추는 정도, 저속 실속 저항 — 중전투기 계보(F-15형)의 특화 축. |
| 생존 | 속도 (Speed) | 최대/순항 속도 |
| 생존 | 방어 (Defense) | 체력/실드 |
| 공격 | 힘 | 무기 위력 상승 (소울류 STR 참고) |
| 공격 | 기량 | 락온 거리, 명중률, **멀티 락온 개수**에 영향 (소울류 DEX 참고) |

* 공대공/공대지 공격력은 별도 스탯으로 두지 않음 — 무기가 스킬카드로 최대 3개까지 임의 장착되는 방식이라 기체 자체의 계열별 화력 스탯이 불필요. 대신 힘/기량이라는 범용 성장축으로 대체, 에이스컴뱃의 "표준 무기 데미지 고정" 관습을 깨는 RPG적 성장 요소 도입.

### 6.2 스킬카드 3유형
1. **스탯 상승형**: 특정 스탯을 직접 올려주는 카드.
2. **스탯 영향형**: 특정 스탯의 영향을 받아 효과가 변동하는 카드 (예: 무기 데미지 카드가 '힘' 스탯과 곱연산).
3. **스탯 조건형**: 특정 스탯이 임계값에 도달해야 해금되는 카드 (진화 분기 트리거 등).

### 6.3 장비-스탯 연동 원칙
* 소울류처럼 스탯 미달 시 장비 사용에 페널티/제약을 주는 방식은 **채택하지 않음** — 뱀서라이크 특유의 짧은 런 타임(15~30분)과 즉흥적 카드 선택 리듬에는 하드 제약이 부적합하다고 판단.
* 대신: **등장 조건(하드 게이트)과 성능(연속 보정)을 분리**.
  - 장비의 "등장 여부"는 스탯 임계값 조건으로 게이팅 (기존 진화 해금 구조와 동일 문법).
  - 장비를 획득한 이후의 "성능"은 관련 스탯에 따라 연속적으로 보정 — 스탯이 낮아도 사용 자체는 가능, 이후 스탯을 올리면 자연스럽게 효율이 상승하는 구조. "손해"가 아닌 "성장의 여지"로 체감되도록 설계.
* 보정 곡선(선형 vs 소프트캡 S자)은 프로토타입 단계에서 결정.

## 7. 무장 시스템

* 기본 범용 미사일 + 스킬카드를 통해 획득하는 최대 3개까지의 임의 무장 슬롯.

## 8. 적 디자인

* **메카물고기 침략자**로 설정 — 배경 서사와 직결.
* 메카닉 표현 수준: "생체-기계 융합형"이 아닌 **"물고기 형태로 설계된 순수 기계형"**으로 방향 확정 (스페이스 블랙 코의 물고기형 우주선이 오토리도리 메카물고기의 기원이라는 기존 설정과 정합성 유지, AI 하드서피스 생성 파이프라인과의 궁합 고려).
  - 물고기 정체성을 유지하기 위한 최소 앵커: 꼬리지느러미형 추진부, 아가미 위치 대응 패널/배기구, 비늘형 장갑판 패턴, 눈 위치의 센서/콕핏.
* 스타파이터의 6소켓 모듈러 파츠 조합 로직을 재활용해 잡몹 편대의 시각적 다양성을 저비용으로 확보 가능.
* 스타파이터에서 디자인한 메카물고기 에셋은 추후 오토리도리에서도 재활용 가능 (렌더링/셰이더만 프로젝트별로 분리).

## 9. AI 아트 파이프라인

* **데폼 프롬프트 툴 (자체 제작)**: 기종/모델 이름, 배경 프롬프트(기본값 심플 배경, 공란 시 랜덤), 디자인 소스 이미지, 비례 참조 이미지, 메카닉 종류(전투기/전차/자동차), MORPHOLOGY 슬라이더(REAL~EXTREME), 아트 스타일 프리셋(선화&카툰/리얼 PBR/디지털 페인트/박스 일러스트), 구도 지정용 3D 회전 창(방위각·고도각) 등을 파라미터화한 UI 툴.
* 전투기 외 자동차 등 다른 오브젝트에도 동일 로직이 일반화되어 작동함을 확인.
* **슬라이더 LoRA 학습 계획**: LLM 이미지 생성(Google Flow 등)으로 먼저 데폼 비율을 확정 → 그 결과를 학습 데이터로 삼아 SDXL 기반 슬라이더 LoRA를 학습시켜 여러 기종에 걸친 통일성 확보하는 하이브리드 워크플로우. 보유 VRAM 8GB로는 SDXL 학습이 간당간당할 것으로 예상(FLUX보다는 현실적).

## 10. 장기 기획의 열린 질문 / 다음 단계

* 현재 웹 프로토타입은 6종 스탯 모두를 한 런의 공통 카드 풀로 운영한다. 후속 외형 진화에서 계보 분화축과 범용 성장축을 분리할지는 미정이다.
* 웹에는 레트로 후처리와 옵션 토글이 구현되어 있다. 최종 PS1 스타일의 범위 확정과 Unity 셰이더 프로토타이핑은 후속 과제다.
* 버티컬 슬라이스 범위 확정: 6소켓 전체 vs 2~3소켓 + 단일 계보로 축소한 최소 루프 검증판.
* 3개월 포트폴리오 일정 내 완성을 최우선 목표로, 스코프 관리 지속 필요.

## 11. 웹 프로토타입 플레이 규칙 — 2026-09-22 코드 대조

1~10절은 장기 기획 기록으로 유지한다. 현재 동작은 이 절과 [README](../README.md), [개발 문서](../docs/ARCHITECTURE.md)를 기준으로 구분한다.

### 11.1 전투·성장

- 기본 무장은 기관포·표준 미사일·멀티 미사일이다. 추가 무장 3슬롯은 미구현이다.
- 기관포 피해 18, 표준 피해 55·20발 탄창·재장전 기준 15초, 멀티 피해 85·8발 탄창·기준 30초다. 실제 재장전 대기는 발사 누적 부채와 경과 시간에 따라 달라진다.
- 멀티 동시 발사는 기본 4발, 관제 확장으로 6·8발이며 표적 수·잔탄을 넘지 않는다. 출격 전체 총 탄약 한도는 없다. 표준/멀티 랙은 단계당 각각 +4/+2발이다.
- 처치 경험치 즉시 지급, 레벨업마다 선택권 1회 적립. 레벨업 자체는 자동 정지하지 않는다. X 또는 웨이브 전환 시 카드창을 열고 모든 선택권을 소비해야 복귀한다.
- 6종 스탯은 각각 0~5단계다. 기동력 회전속도 +8%, 안정성 응답 배율 +0.15, 속도 순항 +20·최대 +40kts 및 가감속 +8kts/s, 방어력 체력 +20, 화력 피해 배율 +0.1, 관제력 락온 거리 +10%·유도 배율 +0.08이다.
- 기체 초기 속도 최소/순항/최대는 150/550/950kts, 가속/감속은 170/190kts/s다. 초기 피치/롤/요 최대 회전속도는 1.45/2.85/0.55rad/s다.
- 스마트 기총 어시스트와 단계당 보조 반경 +20% 카드가 구현되어 있다. 전체 카드 정의는 14개이며 원본은 `balance/cards.xlsx`다.
- 경험치는 `levels.xlsx`의 60행 테이블을 사용하고 첫 5개 요구량은 60/150/300/500/750이다. 전 구간을 단일 공식으로 설명하지 않는다.

2026-09-22 정적 검사 54개 모듈 통과, 단위 테스트 60개 중 49개 통과·11개 실패다. 같은 날짜에 출격 브라우저 회귀 검사로 세 스테이지 전체 웨이브·보스·정비창 전환을 확인했다. 실제 배치 실행에서 레이더·중앙 HUD·적 표식을 확인했고 사용자가 정상 동작을 확인했다. 모든 밸런스 또는 모든 입력 장치가 검증 완료된 것은 아니다.

다음 정합성 과제는 단위 테스트 실패 검토, 기존 Playwright smoke의 오래된 기대값 정리, 실제 게임/시뮬레이터의 엘리트 생성 정책 통일, 실제 생성 수 기반 엘리트 집계다. 외형 진화·6소켓·새 무장 슬롯은 이와 별도의 장기 범위로 유지한다. 기존 `balance/reports/`는 과거 실험 기록이며 현재 플레이 시간으로 인용하지 않는다.
